# RFC-015: Replace redis-cache with Valkey

**Status:** accepted · **Author:** Sara Kim · **Reviewers:** Deepak Rao, Farhan Qureshi · **Rollout:** Thu 10 Sep 2026, 14:00 IST

## Proposal
Replace `redis-cache` (Redis 7.2 with Sentinel) with `valkey-cache` (Valkey 8.0 with Sentinel). Valkey is protocol compatible; clients only change the host to `valkey-cache.prod.svc.cluster.local`. The Sentinel master name stays `kestrel-cache`.

## Migration
1. Stand up valkey-cache next to redis-cache, replicate, and warm it.
2. Switch auth-svc, ledger-svc and fraud-scorer to the new host behind a config flag.
3. Decommission redis-cache the same afternoon.

## What changes for on-call
- The `redis-cache` service and its Sentinels will no longer exist. Commands in older runbooks such as `redis-cli -h redis-cache -p 26379 ...` must use `valkey-cli -h valkey-cache -p 26379 ...`.
- Failover behaviour and the cold-cache risk (INC-3951) are unchanged; warm-up and request coalescing work the same way.
